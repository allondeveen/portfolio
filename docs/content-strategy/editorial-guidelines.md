# Editorial guidelines

This document defines how content should be written and how visual assets should support it.

## Writing style

The content should read neither as a scientific paper nor as a personal blog.

Use an objective voice to describe:

- The project
- The problem
- Constraints
- Arguments
- Outcomes

Use the first person for:

- Decisions
- Trade-offs
- Responsibilities
- Reflections

The tone should be professional, technical, clear, concise, evidence-based, and engineering-focused.

## Project case studies

Project case studies follow the general writing style. Limit the first person to decisions, trade-offs, responsibilities, and reflections.

## Technical articles

Technical articles should use very little first person, if any. All articles on the website are technical articles and should be written in an objective voice.

## Visual assets

Use diagrams and demos to supplement the writing. Visuals should not replace the written explanation.
