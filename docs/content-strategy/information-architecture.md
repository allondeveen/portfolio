# Information architecture

This document describes how the content is organised. It contains the sitemap, navigation structure, and the journeys users take across the website.

## Sitemap

- Homepage
- Projects
  - Dynamic project page
- Articles
  - Dynamic article page
- Contact

## Navigation

The primary navigation contains:

- Homepage
- Projects
- Articles
- Contact

## User journeys

Every journey should provide a clear path towards making contact. Regardless of whether visitors enter through the homepage, a project page, or an article, they should be able to continue exploring related content and easily navigate to the contact page.

### 1. Contact immediately

The visitor already knows enough and wants to make contact.

`Homepage -> Contact`

### 2. Evaluate engineering experience

The visitor wants to understand previous engineering work.

`Homepage -> Projects overview -> Project page -> Contact`

### 3. Evaluate technical knowledge

The visitor wants to assess technical depth.

`Homepage -> Articles overview -> Article page -> Contact`

### 4. Discover projects through featured content

The visitor discovers a featured project directly on the homepage.

`Homepage -> Featured projects -> Project page -> Contact`

### 5. Discover articles through featured content

The visitor discovers a featured article directly on the homepage.

`Homepage -> Featured articles -> Article page -> Contact`

### 6. Explore related engineering work

The visitor discovers other projects on a project page through related content.

`Project page -> Project page -> Contact`

### 7. Learn about a technical topic

The visitor discovers topic-related articles directly on an article page through related content.

`Article page -> Article page -> Contact`
